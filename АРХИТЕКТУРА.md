# Архитектура проекта SaveTube

## Схема на одной странице

**Части (4 шт.):**
    1.  **Frontend (Next.js UI)** — есть. Отвечает за ввод ссылки и отображение результата.
    2.  **Backend (Next.js API Route)** — есть. Запускает системные утилиты и управляет файлами.
    3.  **База данных (Supabase)** — есть. Хранит статусы задач и общий счетчик.
    4.  **Внешние сервисы (yt-dlp, FFmpeg, Deno, VPN, PO Token)** — есть. Выполняют тяжелую работу по скачиванию и обходу блокировок.

**Данные и где они живут:**
    *   **Текстовые статусы задач и названия треков** — живут на **сервере** (в облачной БД Supabase).
    *   **История скачиваний** — живет в **браузере** (в `localStorage`, максимум 10 записей).
    *   **Готовые MP3-файлы** — живут на **сервере** (локальный диск, папка `public/audio`).

**Три вопроса (с причиной из сценария):**
    *   **Другое устройство?** — **Нет**. История хранится локально в браузере. Пользователю не нужен аккаунт, чтобы скачать трек.
    *   **Общие данные?** — **Да**. Счетчик «успешных конвертаций» виден всем пользователям и обновляется глобально через Supabase.
    *   **Секреты и ключи?** — **Да**. Запросы идут через локальный VPN (порт 7890) и сервер PO Token (порт 4416). Эти данные нельзя отдавать в браузер, поэтому нужен бэкенд.

**Внешние сервисы (и нужен ли ключ):**
    *   **YouTube** — ключ **не нужен** (доступ через библиотеку `yt-dlp`).
    *   **VPN-прокси (локальный)** — ключ **не нужен** (используется локальный порт).
    *   **Сервер PO Token (локальный)** — ключ **не нужен** (генерация токенов на лету).
    *   **Supabase** — ключ **нужен** (URL проекта и Anon Key).

**Дорого менять:**
    *   *Хранение файлов на локальном диске.* Сейчас готовые MP3 лежат в `public/audio`. Если проект вырастет, локальный диск переполнится, и придется переезжать на облачное хранилище (S3 или Supabase Storage).
    *   *Как пересмотреть:* При росте аудитории (например, более 100 конвертаций в день).
    *   *Как подготовиться:* Заранее вынести логику сохранения и удаления файлов в отдельный модуль, чтобы потом легко заменить `fs.writeFile` на `supabase.storage.upload`.

**Технологии:**
    *   Next.js (TypeScript, React)
    *   Tailwind CSS
    *   Supabase (PostgreSQL)
    *   Node.js (child_process, fs)
    *   Системные утилиты: `yt-dlp`, `FFmpeg`, `Deno`. (Все технологии стандартные, новых для вас — не больше одной: Supabase).
